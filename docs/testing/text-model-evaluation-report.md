# 文本模型验证报告

> 日期：2026-08-17  
> 范围：确认后的中文文本 → 自然美式日常英语 → 可独立播放的有序句子  
> 结论：MVP 主模型采用 `qwen3-max` 非思考模式；`qwen3.7-plus` 保留为成本备选。

## 1. 最终配置

- 地域：阿里云百炼华北 2（北京）。
- 模型：`qwen3-max`。
- 模式：非思考模式，`temperature = 0`。
- 输出：JSON Mode + 本地业务校验；Prompt `spoken-en-v7`。
- 数据职责：ASR 确认后的中文原文由后端直接保存，模型只返回 `sentences[]` 和 `metadata`。
- 完整英文段落：由后端按 `sequence` 拼接 `sentences[].english_text`，不保存重复副本。

## 2. 候选结果

| 候选 | 测试规模 | 结构通过 | 平均延迟 | 质量观察 | 决策 |
|---|---:|---:|---:|---|---|
| `qwen-plus` | 30 | 30/30 | 3.77 秒 | 出现生硬搭配、币种改写等问题 | 不采用 |
| `qwen3.7-plus` 非思考 | 30 | 30/30 | 3.86 秒 | 整体可用，但边缘语气和人物关系仍有偏差 | 成本备选 |
| `qwen3.7-max` | 5 | 5/5 | 2.69 秒 | 小样本未改善关键搭配，且价格明显更高 | 不采用 |
| `qwen3-max` v7 | 30 | 30/30 | 3.58 秒 | 关键金额、人物关系、委婉语气与易错搭配整体最佳 | **MVP 主模型** |

各轮 Prompt 并不完全相同，所以表格不是严格学术基准；模型选择同时依据固定难例的同 Prompt 对照和全量人工抽查。

## 4. 测试中发现并修正的问题

1. 模型回显中文原文时曾把“文件”误写成“日消息”。处理方式是删除冗余回显字段，由后端直接保存已确认的 ASR 文本。
2. 早期结果曾把 899 元擅自写成美元。Prompt 现已明确禁止改写数字、单位和币种。
3. 早期结果出现 `happy for you hearing...` 等不自然搭配。v7 增加明确禁令，并在校验器中增加对应错误检查。
4. 模型偶尔把逗号后的片段拆成独立项。后端只做可证明安全的确定性合并，不能修复时触发一次模型重试。

## 5. 仍需保留的产品保护

- 任何 JSON 都必须经过 Schema 与业务规则校验，不能直接入库。
- 自动失败时最多修复重试一次；仍失败则给用户“重新生成”，不要展示半成品。
- 用户可多次重新生成，并明确选择最终保存的版本。
- 上线前还需用真人 60 秒录音完成 ASR 与 TTS 测试；本报告只完成了文本模型选型。
- 正式内测需要母语者或高水平英语教师对真实用户样本抽检，继续维护易错表达回归集。
